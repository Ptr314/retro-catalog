# Каталог программ для ретро-компьютеров

Один процесс Node.js, ноль npm-зависимостей, ноль Docker. Всё, что нужно, уже есть в Node 24:
база — `node:sqlite`, пароли — `node:crypto`, типы — TypeScript срезается на лету, без сборки.

- публичный каталог: семейства компьютеров, их модели, программы с фильтрами и поиском;
- два вида отображения — плитка и таблица, без единой строчки клиентского JavaScript;
- скачивание своего файла и запуск в онлайн-эмуляторах: у программы может быть свой файл под каждый эмулятор;
- описания в Markdown с предпросмотром в админке;
- админка с логином, справочниками, перетаскиванием порядка и загрузкой файлов.

## Требования

Node.js >= 24. Больше ничего: `npm install` делать не нужно, `node_modules` не появляется.

## Быстрый старт

```bash
cp config.example.json config.json   # и поправить siteUrl
npm run user -- add admin "Имя"      # пароль спросит интерактивно
npm start                            # http://127.0.0.1:8080
```

Админка — `/admin`. Сразу после установки заведите хотя бы одно **семейство** (без него нельзя
создать программу) и **эмулятор**, если нужна кнопка запуска.

## Конфигурация

`config.json` рядом с исходниками (в git не попадает, см. `config.example.json`).
Переменные окружения `PORT`, `HOST`, `SITE_URL`, `DATA_DIR` перекрывают файл.

| Ключ | Зачем |
|---|---|
| `siteUrl` | Публичный адрес. Из него строятся **абсолютные** ссылки на файлы для эмуляторов, и по нему cookie сессии получает флаг `Secure`. Должен совпадать с реальным адресом сайта. |
| `corsOrigins` | Кому разрешено скачивать `/files/` и `/screenshots/` кросс-доменно. Если эмулятор на другом домене — укажите его здесь (или оставьте `["*"]`). |
| `maxScreenshotBytes` / `maxFileBytes` | Пределы загрузки. |
| `sessionTtlHours` | Срок жизни сессии админки. |

Адреса эмуляторов больше не в конфиге — они в справочнике «Эмуляторы».

## Как устроено

```
server.ts       HTTP-сервер и маршруты
config.ts       конфиг, каталоги данных, ключ подписи сессий
db.ts           SQLite: схема, миграции, запросы
refs.ts         описания справочников: поля, проверки, правила удаления
reserved.ts     адреса, которые нельзя занять именем семейства
markdown.ts     Markdown → HTML без зависимостей
auth.ts         scrypt-пароли, сессия в подписанной cookie, защита от перебора
http.ts         cookie, тело запроса, отдача файлов (ETag, Range), экранирование, slug
views/          HTML — обычные функции, возвращающие строки
public/         style.css, admin.js, favicon
tools/user.ts   создание пользователя и смена пароля
tools/import.ts массовый импорт из JSON
data/           catalog.db, screenshots/, files/, session-secret  (не в git)
```

### Справочники

Семейства (Агат, БК-0010, …), их модели, эмуляторы и категории программ редактируются в админке
на однотипных страницах `/admin/ref/<таблица>`. Порядок строк задаётся перетаскиванием и
определяет порядок показа на сайте. Программа принадлежит одному семейству и любому числу его
моделей.

### Маршруты

| Метод | Путь | Что делает |
|---|---|---|
| GET | `/` | главная: карточки семейств, `?view=tiles\|table` |
| GET | `/catalog` | все программы: `?q=&family=&model=&category=&year=&sort=&view=&page=` |
| GET | `/:семейство` | страница семейства = каталог с фильтром по нему |
| GET | `/:семейство/:модель` | то же для модели |
| GET | `/p/:slug` | карточка программы |
| GET | `/dl/:slug` | скачивание основного файла, +1 к счётчику |
| GET | `/run/:slug/:эмулятор` | редирект в эмулятор, +1 к счётчикам |
| GET | `/files/:name`, `/screenshots/:name` | статика с CORS и Range |
| GET/POST | `/admin/*` | админка, справочники, администраторы |
| PUT | `/admin/upload/:сущность/:id/:вид` | тело запроса — сам файл |

Форма отправляется как `application/x-www-form-urlencoded`, файлы уходят отдельными PUT-запросами —
поэтому в проекте нет разбора `multipart/form-data`, самой громоздкой части таких задач.

### Ссылка на эмулятор

У каждого эмулятора в справочнике — шаблон с плейсхолдером `{url}`:

```
https://emu.example.com/?machine=agat9&url={url}
```

Вместо `{url}` подставляется адрес файла, загруженного для этой пары «программа + эмулятор»:
`{siteUrl}/files/{имя}`. Плейсхолдер можно поставить куда угодно — в query, в путь или в hash.
Кнопка «Запустить в N» появляется только у тех эмуляторов, для которых файл загружен.
Так как пакет качает сам эмулятор, `/files/` отдаётся с `Access-Control-Allow-Origin` и поддерживает `Range`.

### Описания

Хранятся и редактируются как Markdown, в редакторе две вкладки — текст и предпросмотр.
Поддерживаются заголовки, **жирный**, *курсив*, `код`, ограждённые блоки, списки, цитаты,
горизонтальные линии и ссылки. Картинок в разметке нет намеренно: иллюстрации загружаются
полями формы, а `![](…)` тянул бы стороннюю ссылку на страницу с запрещающим это CSP.

### Безопасность

- пароли — scrypt со случайной солью, сравнение постоянного времени;
- сессия — cookie `HttpOnly`, `SameSite=Lax`, подписанная HMAC-SHA256; таблицы сессий нет;
- POST/PUT принимаются только со своего Origin (плюс `SameSite=Lax`);
- Markdown экранируется целиком **до** разбора, поэтому чужой тег в вывод не попадает, а
  `javascript:`-ссылки теряют ссылочность; CSP запрещает инлайновые скрипты и стили;
- тип картинки определяется по сигнатуре файла, а не по заголовку от клиента;
- файлы программ отдаются как `application/octet-stream` + `nosniff` + `Content-Disposition: attachment`;
- перебор пароля тормозится счётчиком попыток по IP.

## Импорт

```bash
npm run import -- catalog.json
```

Формат описан в шапке `tools/import.ts`. Семейство и модели указываются по slug или названию и
должны существовать заранее; строка с неизвестной ссылкой пропускается с сообщением.
Совпадение по `slug`: существующая запись обновляется, новая создаётся.

## Деплой

Пошаговая инструкция — в [DEPLOY.md](DEPLOY.md): Ubuntu 24.04, Node 24, nginx + certbot (или Caddy на чистом сервере), код из git, обновление и бэкап.
Коротко: нужен HTTPS-домен (эмулятор скачивает файлы сам, по `http://` браузер это заблокирует),
а всё состояние сайта — это `data/catalog.db`, `data/files` и `data/screenshots`.

## Что можно добавить позже

- RSS/Atom новых поступлений;
- превью-миниатюры (сейчас картинка отдаётся как есть и ужимается стилями);
- вторая роль пользователей, если редакторов станет больше одного;
- полнотекстовый поиск через FTS5 вместо `LIKE`, если записей станет десятки тысяч.
